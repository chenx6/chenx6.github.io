我手里有一个几年前买的戴记严选 GM3323D鼠标，这个鼠标为数不多的缺点就是他只能在 Windows 上进行设置鼠标的灯光特效，所以趁着现在有空赶紧对他的驱动进行逆向和移植。

逆向工程

查看安装目录可以看到 "GM3323D.exe" 和 "hiddriver_1.dll", "hiddriver_2.dll" 这几个明显的文件，还有 "DuiLib.dll" 这种第三方库，"res" 文件夹里放的是资源文件，包括程序布局，贴图。我们先都记下来。

安装目录下还放了第三方库的开源许可协议，给这个公司点赞！

编写程序

通过分析 "hiddriver_2.dll" 我们可以知道程序是通过 HidD_SetFeature 函数将设置发送给设备的，在 Linux 下则是通过万能的 ioctl 往 /dev/ 下的设备里写入设置。下面的代码是通过 HID_ID 来找到鼠标设备，并通过 ioctl 函数将设置传给鼠标。

HIDIOCSFEATURE = lambda n: (3 << 30) | (n << 16) | (0x48 << 8) | 0x06


def find_dev(vid: int, pid: int):
    for folder in Path("/sys/class/hidraw/").iterdir():
        uevent = folder / "device/uevent"
        if f"HID_ID=0003:{vid:08X}:{pid:08X}" in uevent.read_text():
            return "/dev/" + folder.name


def write_report5(fd, buf: bytearray):
    assert len(buf) == 13 and buf[0] == 5
    n = ioctl(fd, HIDIOCSFEATURE(13), buf, True)
    return n

接下来的主函数就简单了，直接找到设备，读取要修改的参数，应用到设置模板里，写入到设备。

def main():
    path = find_dev(0x1D57, 0xFA60)
    if not path:
        print("Device not found")
        return
    parser = ArgumentParser()
    parser.add_argument("-p", "--profile", type=int, default=1)
    parser.add_argument("-m", "--mode", type=int, default=1)
    parser.add_argument("-c", "--color", default="FF 48 B0")
    parser.add_argument("-d", "--duration", type=int, default=4)
    parser.add_argument("-b", "--brightness", type=int, default=8)
    parser.add_argument("--battery", action="store_true")
    args = parser.parse_args()
    if args.battery:
        monitor_battery(path)
        return
    profile = int(args.profile)
    mode = int(args.mode)
    color = bytes.fromhex(args.color)
    duration = int(args.duration)
    brightness = int(args.brightness)
    tmpl = bytearray.fromhex("05 0D 01 02 04 08 FF 48 B0 06 01 00 00")
    tmpl[2] = profile
    tmpl[3] = mode
    tmpl[4] = duration
    tmpl[5] = brightness
    tmpl[6:9] = color
    print("Writing", tmpl, "to", path)
    with open(path, "rb+", buffering=0) as fd:
        n = write_report5(fd, tmpl)
        print(f"Write {n} bytes")

附加题：设备电量

设备电量有点迷惑，我在驱动程序里看到有显示电量数字和图标的地方，于是就搜索 "power" 相关字段，但是只能定位到和 GUI 相关的地方，然后再搜索 "%d%%" 才定位到 "sub_416C90" 函数，这个函数负责将电量数字显示到 GUI 上。通过 xref 找到上游 "sub_40B140" 函数，这个函数跑到 const CMainWnd::`vftable' 里去了。因为又有一堆的 switch, 所以我猜测又是一个处理事件的函数。

大模型：

你看程序在初始化的时候执行了 *(this + 11) = (HMODULE)Open_DevMonitor;，然后程序里又调用了 (*((void (__cdecl **)(_DWORD, int, int))lpParameter + 11))(*((_DWORD *)lpParameter + 89), 1331, 1332); 函数指针，等价于调用了 Open_DevMonitor 函数，并将 1331 作为第二个参数 a2 传递了。

再看看 Open_DevMonitor 函数里 dword_1001410C = a2; 有这样的赋值，最后在调用 PostMessageA(hWnd, dword_1001410C, (unsigned __int16)v5, v6); 的时候，就相当于把电池数据传递给了 sub_40B140

我：妙啊。我还在想看不出来就去动态调试了，没想到静态分析也能看出来这么离谱的函数指针调用。

按照这个思路在 "hiddriver_2.dll" 找到了 sub_10001A80 函数，这个函数读取了设备文件。我们也照猫画虎，直接读取设备文件并解析。

def monitor_battery(p: str):
    f = os_open(p, O_RDONLY)
    data = read(f, 64)
    sub = data[1]
    group = data[2]
    charging = bool(data[3])
    level = int(data[4])
    if group != CMD_GROUP:
        return
    print(f"Battery status: {level * 10}%, Charging: {charging}")
